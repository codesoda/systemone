## v0.1.0 — first `s1` binary release

**What works**

- `s1 serve`: resident Jev-compatible HTTP API (`POST /v1/systemone`, `GET /v1/models`, `GET /v1/backends`, `/healthz`, `/readyz`) with bearer auth off-loopback, bounded admission, deadlines and graceful shutdown.
- `s1 run` (single request or `--jsonl` batch), `s1 call`, `s1 decide|noul|score`, `s1 backends`, `s1 models`, `s1 config check|show`, `s1 openjev models pull|path`, `s1 openjev probe`.
- OpenJev backend via `openjev-core`/`openjev-llama` pinned at `8452ef0`, with pinned, SHA-256-verified GGUF models (`qwen3-0.6b`, `minicpm5-2b`, `qwen3.5-4b`).
- Layered configuration: built-ins < `~/.systemone/systemone.config.toml` < `./systemone.config.toml` < `SYSTEMONE_*` < CLI.

**Verified**

- Apple Silicon / Metal with `qwen3-0.6b`: `s1 run`, `s1 serve` + `s1 call`, the official `@typesafe-ai/sdk@0.6.0` smoke, `s1 openjev probe --mode shared` (fails the frozen gate as upstream did, so execution stays `serial` and says so).
- Both targets: fmt, clippy `-D warnings`, 60 workspace tests, packaging tests, license bundle check, CMake configuration, archive contents and dynamic linkage.

**Not verified / not included**

- Linux x86-64 archive has not been run with real model weights.
- No Windows build. No Laya, GLiNER2, Vercel or OpenRouter adapters (enabling one is a configuration error, not a silent fallback).
- Shared/batched execution is never enabled without a passing local probe receipt; every profile measured so far fails the gate. No speedup is claimed.
- `eval`/`bench` are not exposed. The macOS binary is not signed or notarized.
